# 审查修复与验证说明

## 已修复

- 编辑器自动保存保留发布状态，仅保存变更，自动/手动写入串行化。
- Markdown 自定义容器标题、代码块语言与 PlantUML 错误文本进行 HTML 转义。
- Markdown 按文章页面加载；代码高亮仅注册常用语言。未知语言降级纯文本。
- 用户缓存损坏安全降级；文章切换/列表查询忽略过期响应。
- JWT 每次读取当前用户状态、角色和密码版本，禁用/降权/改密不再信任旧令牌权限或缓存。
- 浏览量本地计数原子取出，失败恢复；Redis 使用待确认批次、租约锁和 SCAN。
- 文章创建/更新提交后失效旧缓存；为防止下架数据被在途旧读取回填，详情/热门/最新直接读数据库，不再使用文章快照缓存。
- 文章列表仅查询必要字段，不读取完整正文；标签文章计数只统计已发布文章。
- ZIP 解压约束路径、条目数（10,000）、单文件（64 MiB）和总大小（256 MiB）；备份 ID 白名单；导入/恢复数据库写入增加事务。
- 备份目录配置化、启动时探测可写性；生产 Compose 增加备份与附件持久卷。
- Redis 使用 Boot 3 的 `spring.data.redis` 连接配置和自动配置，保留 `spring.redis.enabled` 自定义开关。

## 验证

后端使用 Java 17：

```sh
cd backend
mvn test
mvn package
```

前端不需要新增依赖：

```sh
cd frontend
npm test
npm run build
```

回归测试不依赖正在运行的数据库和 Redis；涉及故障场景的计数/鉴权测试使用 Mockito。生产环境实际连接、容器运行与浏览器端到端行为仍需部署环境验收。

## 部署注意

1. 重新构建后端镜像和前端静态产物，代码变更不会自动更新已运行容器。
2. 新 Redis 标准环境变量为 `SPRING_DATA_REDIS_HOST`、`SPRING_DATA_REDIS_PORT`、`SPRING_DATA_REDIS_PASSWORD`；配置文件暂兼容旧的 `SPRING_REDIS_*` 环境变量。`REDIS_ENABLED` 开关保留。
3. 生产备份目录为 `/app/backups`，可用 `BACKUP_DIRECTORY` 覆盖。Compose 新增 `backup_data`、`upload_data` 命名卷。
4. **在重建旧容器前**，先导出旧容器中的 `/app/backups` 和 `/app/uploads`，再迁移到新卷。新卷不会自动读取旧容器可写层；不要使用 `docker compose down -v` 删除卷。
5. 旧备份 ID 格式仍受支持；新备份文件名增加毫秒与随机后缀以避免同秒覆盖。备份仍为 QBlog 2.0 JSON ZIP 格式；超出解压限制的大型备份会被拒绝。
6. 不需要数据库结构迁移。本次没有自动执行服务器更新或操作线上文章。

## 明确边界

- 浏览量采用至少一次交付：数据库已提交但 Redis 确认前宕机、网络结果不确定或锁租约过期，可能重复计数。跨 Redis/MySQL 的恰好一次需要持久批次 ID 和数据库幂等事务，当前未宣称实现。
- Redis 不可用时的本地计数仅保存在进程内，进程终止仍可能丢失。
- 下架安全优先于文章快照缓存命中率；热点读取增加数据库访问，后续应在压测与版本化缓存设计后恢复缓存，而不是直接恢复旧逻辑。
- 数据库恢复事务不能与附件文件系统形成分布式原子事务；恢复前应额外保存当前数据库与附件副本，附件恢复仍需核对。
- 本次在已知不安全插值处转义，没有引入 HTML 白名单净化库；未来新增 Markdown 插件仍需遵守同样的输出转义规则。
